The *Composite Pattern* is a design pattern that allows you to treat individual objects and compositions of objects uniformly. It is often used to represent part-whole hierarchies, where you can treat both individual objects and groups of objects in the same way.

Let's examine a typical example of the Composite Pattern. When we develop an application that draws shapes on the screen (such as circles, squares, etc.) we want to use a common interface for all shapes. Using this interface, we can draw or inflate (scale) individual shapes without worrying about their specific types. This is typical example of polymorphism.

The type hierarchy for the shapes might look like this:

```cpp
struct Coordinates
{
    int x;
    int y;
};

class Shape
{
public:
    virtual void draw() const = 0;   
    virtual void inflate(int factor) = 0; 
    virtual ~Shape() = default; 
};

class Circle : public Shape
{
    Coordinates position_;
    int radius_;
public:
    Circle(const Coordinates& pos, int r) : position_(pos), radius_(r) {}

    void draw() const override
    {
        std::cout << "Drawing a circle at " << position_ 
                  << " with radius " << radius_ << std::endl;
    }

    void inflate(int factor) override
    {
        radius_ *= factor;
    }
};

class Rectangle : public Shape
{
    Coordinates position_;
    int width_;
    int height_;
public:
    Rectangle(const Coordinates& pos, int w, int h) : position_(pos), width_(w), height_(h) {}

    void draw() const override
    {
        std::cout << "Drawing a rectangle at " << position_ 
                  << " with width " << width_ 
                  << " and height " << height_ << std::endl;
    }

    void inflate(int factor) override
    {    
        width_ *= factor;
        height_ *= factor;
    }
};
```

Client code can use this interface to operate uniformly on the collection of shapes:

```cpp
void clients_code(const std::vector<std::unique_ptr<Shape>>& shapes)
{
    for (const auto& shape : shapes)
    {
        shape->draw();
        shape->inflate(2);
        shape->draw();
    }
}

std::vector<std::unique_ptr<Shape>> create_shapes()
{
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(Coordinates{10, 20}, 5));
    shapes.push_back(std::make_unique<Rectangle>(Coordinates{30, 40}, 10, 20));
    return shapes;
}

std::vector<std::unique_ptr<Shape>> shapes = create_shapes();
clients_code(shapes);
```

## Grouping shapes as composite objects

One of the basic functionalities in every graphics application is ability to group couple of shapes together. We can treat such a group as a single shape. We can draw or inflate the group as a whole, and the individual shapes will be drawn or inflated accordingly. This is where the *Composite Pattern* comes into play. The key idea is to define a class that represents (aggregates) a group of shapes, and this class implements the same interface as the individual shapes. This way, we can treat both individual shapes and groups of shapes in the same way. Let's implement this:

```cpp
class ShapeGroup : public Shape // inherits from Shape, so it can be treated as a single shape
{
    std::vector<std::unique_ptr<Shape>> shapes_; // aggregates (owns) a group of shapes
public:
    ShapeGroup() = default;

    void add_shape(std::unique_ptr<Shape> shape)
    {
        shapes_.push_back(std::move(shape));
    }

    void draw() const override
    {
        std::cout << "Drawing a group of shapes:" << std::endl;
        for (const auto& shape : shapes_)
        {
            shape->draw();
        }
    }

    void inflate(int factor) override
    {
        for (const auto& shape : shapes_)
        {
            shape->inflate(factor);
        }
    }
};
```

Defining a composite class has several benefits.

1.  It allows us to treat individual shapes and groups of shapes uniformly - it will simplify the client code. The client doesn't have to manage individual shapes and groups of shapes (`std::vector<std::unique_ptr<Shape>>`) separately.
    
    Now the `clients_code()` function is greatly simplified. It doesn't have to iterate over the collection of shapes and call `draw()` and `rotate()` on each shape separately. Instead, it can simply call `draw()` and `rotate()` on the group, and the group will take care of calling these methods on each individual shape.
    

```cpp
void clients_code(ShapeGroup& group)
{
    group.draw();
}
```

2.  It allows us to create complex shapes by combining simple shapes. We can create a complex shape by grouping together several simple shapes, and then we can treat the complex shape as a single entity.
    

```cpp
ShapeGroup smiley_face;
smiley_face.add_shape(std::make_unique<Circle>(Coordinates{50, 50}, 20)); // face
smiley_face.add_shape(std::make_unique<Circle>(Coordinates{40, 60}, 5)); // left eye
smiley_face.add_shape(std::make_unique<Circle>(Coordinates{60, 60}, 5)); // right eye
smiley_face.add_shape(std::make_unique<Rectangle>(Coordinates{45, 40}, 10, 5)); // mouth

clients_code(smiley_face);
```

3.  And last but not least it allows to create hierarchies of shapes (this is one of the main advantages of the Composite Pattern). In graphics application we can introduce a concept of layers. Each layer can contain several shapes, and we can treat each layer as a single shape. We can draw or rotate the entire layer, and all the shapes in the layer will be drawn or rotated accordingly.
    

```cpp
auto layer1 = std::make_unique<ShapeGroup>();
layer1->add_shape(std::make_unique<Circle>(Coordinates{10, 20}, 5));
layer1->add_shape(std::make_unique<Rectangle>(Coordinates{30, 40}, 10, 20));

auto layer2 = std::make_unique<ShapeGroup>();
layer2->add_shape(std::make_unique<Circle>(Coordinates{50, 60}, 15));
layer2->add_shape(std::make_unique<Rectangle>(Coordinates{70, 80}, 20, 30));

// create a drawing that contains multiple layers of shapes
ShapeGroup drawing{};
drawing.add_shape(std::move(layer1));
drawing.add_shape(std::move(layer2));

// pass the drawing to the client code, which can treat it as a single shape
clients_code(drawing);
```

## Copying Composites

When we have a composite structure, we often want to be able to copy it. Each of leaf types (like `Circle` or `Rectangle`) can be copied individually (their classes behave like , but copying a composite structure requires creating a deep copy of the entire structure. At this point we are facing a typical problem with polymorphic objects - how to copy them when we only have a pointer or reference to the base class (thus we don't know the actual type of the object). To solve this problem, we can use the *Prototype Pattern*. The idea is to define a `clone()` method in the base class that returns a pointer to a new copy of the object. Each derived class will implement this method to return a copy of itself. The clone operation can be perceived as a "virtual copy constructor".

```cpp
class Shape
{
public:
    virtual void draw() const = 0;   
    virtual void rotate() const = 0; 
    virtual std::unique_ptr<Shape> clone() const = 0; // new method for cloning shapes

    virtual ~Shape() = default;
};
```

The implementation in a concrete class of `clone()` operation looks like this:

```cpp
class Circle : public Shape
{
  Coordinates position;
  int radius;
public:
  Circle(const Coordinates& pos, int r) : position(pos), radius(r) {}

  /* rest of implementation */
        
  std::unique_ptr<Shape> clone() const override
  {
    return std::make_unique<Circle>(*this); // create a new Circle by copying the current one (using the copy constructor)
  }
};
```

Now we can rely on the clone method to create new shapes based on existing ones without needing to know their concrete types. Implementation of composite type looks like this:

```cpp
class ShapeGroup : public Shape
{
  std::vector<std::unique_ptr<Shape>> shapes_; // aggregates (owns) a group of shapes 
public:
  ShapeGroup() = default; 

  ShapeGroup(const ShapeGroup& other) // copy constructor for deep copying the shapes in the group
  {
    shapes_.reserve(other.shapes_.size()); 

    for (const auto& shape : other.shapes_)
    {
      shapes_.push_back(shape->clone()); // clone each shape and add it to the new group
    }
  }

  ShapeGroup& operator=(const ShapeGroup& other) 
  {
    ShapeGroup temp(other); // create a temporary copy of the other object (using the copy constructor)
    swap(temp);   // swap the contents of this object with the temporary copy (temp)
    return *this; // return the current object (after the swap)
  }

  void swap(ShapeGroup& other) noexcept // swap function for the copy-and-swap idiom
  {
    std::swap(shapes_, other.shapes_); // swap the shapes vector of this object with the other object
  }

  ShapeGroup(ShapeGroup&&) = default; // move constructor
  ShapeGroup& operator=(ShapeGroup&&) = default; // move assignment operator

  void add_shape(std::unique_ptr<Shape> shape)
  {
    shapes_.push_back(std::move(shape));
  }

  void draw() const override
  {
    std::cout << "Drawing a group of shapes:" << std::endl;
    for (const auto& shape : shapes_)
    {
      shape->draw();
    }
  }

  void inflate(int factor) override
  {
    std::cout << "Inflating a group of shapes:" << std::endl;
    for (const auto& shape : shapes_)
    {
      shape->inflate(factor);
    }
  }  

  std::unique_ptr<Shape> clone() const override
  {
    return std::make_unique<ShapeGroup>(*this); // create a new ShapeGroup by copying the current one (using the copy constructor)
        }
  };
```

Implementation of the `clone()` method in the `ShapeGroup` class forces us to implement copy constructor that performs a deep copy of the aggregated shapes. This leads us to application of *Rule of Five* - we have to provide all five special member functions (copy constructor, copy assignment operator, move constructor, move assignment operator, and destructor) to ensure that composite objects are copied and moved correctly and efficiently.

### CRTP and Cloning

Implementation of the `clone()` method in each derived class is repetitive. We can use the *Curiously Recurring Template Pattern* (CRTP) to eliminate this redundancy. The idea is to define a template base class that implements the `clone()` method, and then each derived class can inherit from this template base class, passing itself as a template parameter. This way, we can implement the `clone()` method once in the template base class, and it will work for all derived classes without needing to implement it in each derived class.

```cpp
class Shape
{
public:
  virtual void draw() const = 0;   
  virtual void rotate() const = 0; 
  virtual std::unique_ptr<Shape> clone() const = 0; // new method for cloning shapes

  virtual ~Shape() = default;
};

template <typename TShape, typename TShapeBase = Shape>
class CloneableShape : public TShapeBase
{        
public:
  using TShapeBase::TShapeBase; // inherit constructors from the base class

  std::unique_ptr<Shape> clone() const override
  {
    return std::make_unique<TShape>(static_cast<const TShape&>(*this));
  }
};

class Circle : public CloneableShape<Circle>
{
  Coordinates position_;
  int radius_;
public:
  Circle(const Coordinates& pos, int r) : position_(pos), radius_(r) {} 

  void draw() const override { /* implementation */ }

  void inflate(int factor) override { /* implementation */ }
            
  const Coordinates& position() const { return position_; }
  int radius() const { return radius_; }
};

class ShapeGroup : public CloneableShape<ShapeGroup>
{
  std::vector<std::unique_ptr<Shape>> shapes_; // aggregates (owns) a group of shapes
public:
  ShapeGroup() = default; 

  ShapeGroup(const ShapeGroup& other) // copy constructor for deep copying the shapes in the group
  {
    shapes_.reserve(other.shapes_.size()); 

    for (const auto& shape : other.shapes_)
    {
      shapes_.push_back(shape->clone()); // clone each shape and add it to the new group
    }
  }

  ShapeGroup& operator=(const ShapeGroup& other) // copy assignment operator for deep copying the shapes in the group
  {
    if (this != &other) // check for self-assignment
    {
      ShapeGroup temp(other); // create a temporary copy of the other object (using the copy constructor)
      swap(temp);   // swap the contents of this object with the temporary copy (temp)
    }
    return *this; // return the current object (after the swap)
  }

  void swap(ShapeGroup& other) noexcept
  {
    std::swap(shapes_, other.shapes_); // swap the shapes vector of this object with the other object
  }

  ShapeGroup(ShapeGroup&&) = default; // move constructor
  ShapeGroup& operator=(ShapeGroup&&) = default; // move assignment operator

  void add_shape(std::unique_ptr<Shape> shape)
  {
    shapes_.push_back(std::move(shape));
  }

  void draw() const override
  {
    std::cout << "Drawing a group of shapes:" << std::endl;
    for (const auto& shape : shapes_)
    {
      shape->draw();
    }
  }   

  void inflate(int factor) override
  {
    std::cout << "Inflating a group of shapes:" << std::endl;
    for (const auto& shape : shapes_)
    {
      shape->inflate(factor);
    }
  }
};
```

Our solution tries to reduce redundancy in the implementation of the `clone()` but still is far from being perfect. We still have to remembrer to inherit from the `CloneableShape` class. This is crucial - if we forget to override the `clone()` implementation from the base class, we will end up with nasty bug. The client will get inproper clone of the shape, and it will be very hard to track down the issue. This is the result of violation of the *Liskov Substitution Principle* - we can't substitute a derived class for its base class without affecting the correctness of the program.

```cpp
class EvilCircle : public ColorCircle // BEWARE!!!
{
public:
  EvilCircle(const Coordinates& pos, int r, const std::string& color) 
    : ColorCircle(pos, r, color) {}

  void draw() const override
  {
    std::cout << "Drawing an evil " << color() << " circle at " << position() << " with radius " << radius() << std::endl;
  }
};

void lsp_violation()
{
  auto evil_shape = std::make_unique<PrototypePattern::CRTP::EvilCircle>(Coordinates{50, 60}, 15, "black");
  evil_shape->draw();

  std::unique_ptr<PrototypePattern::CRTP::Shape> cloned_shape = evil_shape->clone(); // this will call the clone() method of the ColorCircle class, which creates a new ColorCircle object, not an EvilCircle object
  cloned_shape->draw(); // this will call the draw() method of the EvilCircle class, which is not expected when treating it as a Shape
}
```

This trap can be mitigated by using *Template Method Pattern* (idea presented by Andrei Alexandrescu in his famous book *Modern C++ Design*). The idea is to define a non-virtual `clone()` method in the base class that calls a virtual `do_clone()` method and checks if the type of the returned object matches the expected type. Still we have to implement the `do_clone()` method in each derived class, but at least we have a safety check in place to prevent the issue of forgetting to override the `clone()` method.
